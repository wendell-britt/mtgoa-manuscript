## Error Pattern 1 — Altitude/Color Misalignment

**What:** Q2 written as "where the Architect's Blue operates through structure and the Challenger's Orange through autonomous individual agency" — both wrong. Architect is Orange, Challenger is Red.

**How it happened:** Assumed mapping from memory without consulting existing corpus. Confidence without verification.

**Detection:** User caught it during review — "The Architect is orange, and the Challenger is Red."

**Fix applied:** Corrected all cross-references in Q2 to reflect actual altitudes. Regent=Blue, Challenger=Red.

**Why this matters structurally:** The book is cross-referential. If every chapter has wrong altitude/color signals for other faces, the reader accumulates false information. This is not a style issue — it is a factual consistency issue.

## Error Pattern 2 — Emotional Alchemy Framework Invented Mid-Draft

**What:** When building Price-Namer channel (Q3), I generated move structures that don't exist in the Shaman's framework: "Control 3 → labeled dissatisfaction move to a neutral channel," treating Neutral Channel as an emotional type. The Neutral Channel is a structural/behavioral category, not an emotional category. The emotions being alchemized sit on the Dissatisfaction side, not the Control side.

**How it happened:** Attempted to derive the emotional alchemy architecture from first principles instead of reading the Shaman chapter. Was reasoning from incomplete information.

**Detection:** User pushed — "neutral channel energy in this pattern is shame... this isn't reflected in the emotional alchemy literature. Dissatisfaction is what creates shame." User's reframe: "we're talking about emotional alchemy moves. HOW does one use emotional alchemy to be a better price namer."

**Fix applied:** Rebuilt Price-Namer alchemy with explicit emotion labels on every Dissatisfaction move, correct triplet structure (Transcend/Translate/Control per Dissatisfaction), and correct Neutral Channel framing (structural/behavioral pattern, not an emotion).

**Why this matters:** The CYOA structure means a reader might encounter any chapter first. Every move needs the emotion labeled explicitly so it can be traced back to the WAVE-Spiral fundamentals in Chapter 2. Inferred frameworks don't survive contact with a reader who doesn't have the assumed context.

## Error Pattern 3 — No Save Discipline Until Reminded

**What:** Drafted Q1, Q2, and partial Q3 without writing to disk. No timestamped file created until user explicitly asked whether work had been saved.

**How it happened:** Informal drafting mode — assumed conversation continuity was sufficient. Did not follow the "timestamped file on acceptance" protocol.

**Detection:** User asked directly — "Have what we've drafted been saved yet?"

**Fix applied:** Saved to `DRAFT_Q1-Q2_2026-04-20.md`, then updated to `DRAFT_Q1-Q3-Channels-Alchemy_2026-04-20.md` when Q3 was completed.

**Why this matters:** Conversation continuity is not durable storage. A session cut or connection loss would have erased everything before the save point.

### Pattern 11: Face Cross-Reference Verification

**Rule:** Before drafting any cross-reference to another face (altitude, color, stage name), read the target chapter's SPEC.md first. Confirm altitude and color before writing comparative language.

**Why it matters:** Memory is unreliable. The book has 8 chapters with 6 faces at different altitudes. Cross-references built from memory accumulate errors that the user will catch and must then correct.

**Companion:** AAR Chapter 6 Diplomat Session, 2026-04-20

### Pattern 12: Shaman Framework Must Be Read, Not Inferred

**Rule:** When drafting any chapter's emotional alchemy section, read the Shaman chapter's full framework first — WAVE-Spiral, energy economy (+2/+1/-1), move types (Dissatisfaction → Satisfaction / Translate / Control), and channel definitions. Do not infer the framework from partial memory.

**Why it matters:** The emotional alchemy system is defined in Chapter 2. Each subsequent chapter applies it to a different face's material. Inferring the architecture produces wrong structures (e.g., treating Neutral Channel as an emotion type). The Shaman chapter is the authoritative source — it must be read.

**Companion:** AAR Chapter 6 Diplomat Session, 2026-04-20

### Pattern 13: Every Dissatisfaction Move Gets an Explicit Emotion Label

**Rule:** In any emotional alchemy move, state the feeling name before the alchemical transformation. The emotion must be named explicitly — not embedded in the role-pattern label (martyrdom, threat-pattern, etc.).

**Format:** [DISSATISFACTION → SATISFACTION] Transcend X — **{Emotion Name}** → *{Alchemical Outcome}*

**Why it matters:** CYOA readers may encounter any chapter first. Without explicit emotion labels, the move has no hook — the reader cannot trace it back to the WAVE-Spiral fundamentals or apply it to their own material. Role-pattern labels alone (martyrdom, collapse) are not sufficient; they describe the pattern, not the emotion running it.

**Companion:** AAR Chapter 6 Diplomat Session, 2026-04-20

### Pattern 14: Neutral Channel Is Structural, Not Emotional

**Rule:** The Neutral Channel refers to behavioral/structural patterns (e.g., untracked depletion, vague threat-pattern, collapse-pattern), not emotional categories. The emotions being alchemized sit on the Dissatisfaction side of the move.

**Why it matters:** Confusion between structural patterns and emotional categories leads to mislabeling moves and incorrect framework application. Neutral Channel moves (Control) redirect behavioral patterns — they do not have their own emotion type. The emotion is on the Dissatisfaction being addressed.

**Companion:** AAR Chapter 6 Diplomat Session, 2026-04-20

### Pattern 15: Save Discipline — Timestamp on Acceptance

**Rule:** Every time the user accepts a draft section, save it immediately to a timestamped file in the format `DRAFT_{section identifiers}_{YYYY-MM-DD}.md`. Do not wait until end of session.

**Why it matters:** Conversation continuity is not durable storage. A session cut erases everything before the last save. The timestamp convention exists so that multiple saves of the same section can be distinguished and the latest version identified quickly.

**Companion:** AAR Chapter 6 Diplomat Session, 2026-04-20
